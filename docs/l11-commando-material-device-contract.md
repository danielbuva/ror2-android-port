## Exact hypothesis and implementation boundary

The original RuntimeSkin.ApplyAsync result can supply the three measured mesh/material records; original CharacterModel material selection can populate renderer slots in an explicitly detached display context; an Android-built shader consuming the recovered material's albedo, tint and emission properties can visibly render that result on Vulkan. The shader is an authored minimum replacement, not recovered desktop shader parity.

Extend tools/unity/ControllerAddressProbe.cs, the existing LoadingSceneProbe render-only display and scripts/lab/scene_runtime.py patterns. Add one thin ./dev preparation/action only if needed. Use the J38 checkpoint/stage as the parent, not the active J60 platform probe. Preserve all 45 original assembly hashes for this experiment; neither J55's audio patch nor platform startup is required. Do not rebuild generic workflow infrastructure.

1. Restore/verify the J38 closure and invoke its original load/bake/ApplyAsync sequence with existing status, identity and ownership assertions. Keep the gameplay prefab inactive. No application startup coroutine, Run, platform/profile initialization, Wwise prefab activation or native calls are requested.
2. Use the original CharacterModel.InitSharedMaterialsArrays once in this fresh process, through narrowly preserved reflection. This is diagnostic invocation of one initializer, not completion of the PostProgressBar phase. Invoke original UpdateRendererMaterials for each of the three real renderer records. Use an explicitly detached display context: body is null, visibility Visible, no overlays/ghost/doppelganger state. Record any temporary context field assignments and restore them. Preserve each record's measured ignoreOverlays value. Do not rewrite the methods, fake catalogs, or invoke the broad CharacterModel lifecycle/UpdateMaterials/UpdateOverlays.
3. Assert before/after renderer slot count and material object identity against each original ApplyAsync record. The harness must not assign the expected material to these source renderer slots. Failure of original selection or identity is a failed experiment even if a preview can be drawn.
4. Build one authored Android shader/material conversion for this measured family. Map the recovered _MainTex with scale/offset, _Color, _EmTex, _EmColor and _EmPower. The defined minimal shading contract is fixed diagnostic diffuse lighting on tinted albedo plus emission texture RGB × emission color RGB × emission power. Do not infer proprietary shader equations or map unused properties speculatively. Reuse the accepted albedo-only shader as the control. No normal-map support is needed for the inspected material (its _NormalTex reference is null). Record unsupported desktop features, including limb removal/dither/overlays; do not claim parity.
5. Reuse the existing transform/renderer-only display bridge: copy the measured meshes, bones, pose and *original-assignment output materials* into its renderers, replacing only their shader with the authored conversion in owned material copies. This explicit copy is diagnostic display plumbing, not original CharacterModel rendering/lifecycle integration. Retain the same input/output material mapping for all three renderers. Never silently fall back to a manually supplied preview material on a failed source assignment.
6. Render a fixed pose/camera on the authorized Vulkan device with albedo-only control, converted emission disabled, and converted emission enabled, then restore the recovered emission values. Capture each in the current foreground process using existing infrastructure. Use a temporary declared emission multiplier only for a sensitivity control if the original 0.11 value is too subtle; restore it for the acceptance image. No animation/simulation claim from a sampled pose. An absent emission texture is a closure failure, not permission to synthesize one.

## Evidence, pass/failure, rollback

Pass requires original skin and slot-identity assertions for all three renderers; original DLL hashes unchanged; source→converted material/texture/shader identities and selected shader support recorded; current APK/payload/PID and Vulkan attribution; at least 30 seconds stable runtime; visually reviewed captures showing the recovered model and guns without error-pink/missing textures; and a measured image difference in the model region when emission is toggled, with fixed pose/light/camera and stable background control. shader.isSupported or compilation alone is insufficient. Do not require exact pixel equality across launches. Establish one successful fresh launch, then reproduce once with the same APK/payload in a second fresh process. No full baseline re-run is needed unless a changed dependency warrants it.

First-failure order: accepted input/closure → original ApplyAsync → initializer/reflection/AOT → original renderer assignment/identity → converted texture/material bindings → Android shader compilation/support → on-device visible output/sensitivity → ownership/release cleanup. Stop on the first substantive runtime failure; do not mask exceptions or substitute materials to continue. A failed device result is useful first-failure evidence, not capability acceptance. Ordinary harness compilation and narrow binding mistakes may be repaired within the same contract.

Keep original wrapper/handle cleanup from J38 and release only fixture-owned objects/material copies; preserve original shared assets. Record source context restoration. Reuse existing build/install/run/capture and owned-package safeguards. Query live storage every install; no unrelated data changes. Preserve failed attempts and the J38/J28 APK/payload receipts.
