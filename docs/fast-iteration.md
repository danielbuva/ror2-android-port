# Fast lab iteration

These are current developer actions for the existing IL2CPP ARM64 lab. They do
not change Architecture C, the ownership checks or the normal full-build
acceptance gate. Generated APKs, keys, receipts and logs stay under ignored local
state. Measurements and device findings belong in the journal.

After a normal `./dev prototype --action whole-catalog-build`, authored C#
changes can use:

```sh
./dev preflight --host-only
./dev prototype --action whole-catalog-fast-build
./dev install --device SERIAL --apk APK
./dev sync-data --device SERIAL
./dev check-baseline --device SERIAL
```

Commit build sources before building. The fast action verifies the existing
frozen-payload contract, runs Unity's ordinary native build with its warm Bee
cache, and stops before Gradle. It substitutes the complete generated native
libraries and player assets, including metadata and changed serialized Data,
into the normal-build anchor. Unchanged ZIP records retain their compressed
bytes. Zip alignment, APK verification and the existing signing identity are
required; a v4 `.idsig` is generated beside the APK. Java, manifest or Android
resource drift refuses and requires a normal build. The fast APK is for
iteration; complete acceptance with a normal full build.

Worktrees sharing the primary prepared editor use
`shared-catalog-code-build --full` for the normal anchor, then
`shared-catalog-fast-build` or `shared-catalog-scripts-build`. These reuse the
existing shared-checkout coordinator: it selects the exact committed source in
the primary checkout under the build mutex, invokes the ordinary `./dev` action
and restores primary source afterward. Both checkouts must be clean; unexpected
edits are preserved and refuse restoration. No Unity project is copied. This
also keeps generated transformations inside the primary repository's ignored
work root, as their provenance guards require.

`work/config/iteration-base.json` is generated by normal builds, never supplied
by hand. It identifies the APK and packaging inputs. No timestamped experiment
directory is selected as a build input. The build mutex covers staging through
signature verification and receipt publication. An iteration export is reported
separately from its deliberately cancelled BuildPlayer packaging; the receipt
retains that BuildReport's errors. A failed build before the owned callback or
an unrelated error does not qualify as an export.

`whole-catalog-scripts-build` evaluates the pinned editor's
`BuildOptions.BuildScriptsOnly`. It retains previously serialized player Data;
compare the candidate with a normal build before using it for a change involving
serialization. It shares the same splice/signature checks and never deploys
directly. Unity's
[PatchPackage](https://docs.unity3d.com/2021.3/Documentation/ScriptReference/BuildOptions.PatchPackage.html)
is a different deployment path: the pinned Android processor kills and deploys
to editor-selected targets through its own deployment service. That bypasses
the lab's selected-device storage and ownership receipts and produces an external
patch deployment. It is not dispatched by these actions.

For exact member comparison:

```sh
./dev prototype --action apk-member-compare --compare FIRST_RESULT.json SECOND_RESULT.json
```

Both receipts must name the same source/input/API and unchanged APKs. Every
unsigned member is hashed; random build GUIDs and all other differences remain
visible. ZIP layout and signature bytes can differ while member bytes match.

Installation defaults to explicit streamed installation. To measure Android's
v4/IncFS transport, use `./dev install --device SERIAL --apk APK
--install-mode incremental`. A matching generated `.idsig` and the device's
incremental-delivery feature are required; unsupported installations fail
without falling back to another mode. Android's
[incremental installer](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/dev/incremental-install.md)
prioritizes requested blocks of a new APK. It does not reuse unchanged members
from the previous installation. `--wait` includes completion in the measurement.
Moving audio into APK splits would require a new base/split manifest and proving
Unity/Wwise lookup through that layout; `install-multiple` cannot turn an
existing monolithic APK into byte-delta updates. The separate payload sync
already sends only files whose device hashes differ.

Build receipts include host phases, Unity's inclusive build steps, original
BuildReport outcome, bounded editor-log Gradle durations and Bee compiler work.
Do not sum inclusive steps or parallel jobs as elapsed time. Install and sync
receipts separately record storage checks, hashing and transfers. Debug symbols
remain off unless `--debug-symbols` is explicitly requested on a normal build.
APFS clones keep independent artifact snapshots without duplicating unchanged
disk blocks; ordinary build copies avoid rehashing the same bytes twice.
Forced normal builds retain earlier cache artifacts instead of replacing an
anchor that may still be installed. The generated-output pruner protects the
current iteration anchor alongside normal current-build/device receipts.
